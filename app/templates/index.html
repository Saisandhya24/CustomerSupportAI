Top 5 Failure Modes & Deep Analysis

Real-world failure cases identified during golden dataset evaluation with root cause hypotheses.

Failure Mode #1

Sarcasm & Implicit Frustration Misclassification

Real Example: "Oh fantastic, another update, another feature broken! Thanks @AppleSupport you guys are geniuses."

Observed Behavior: Agent classified tweet as `GENERAL_DEVICE_TROUBLESHOOTING` and generated a generic thank-you reply ("Thanks for reaching out!").

Root Cause Hypothesis: Surface-level TF-IDF keywords ("thanks", "update", "geniuses") triggered positive sentiment matching while missing underlying sarcastic tone.

Failure Mode #2

Compound Multi-Intent Queries

Real Example: "@AppleSupport battery drains in 1 hour AND my iCloud photos stopped syncing after updating to iOS 17!"

Observed Behavior: System forcibly assigned a single intent label (`BATTERY_HARDWARE`), ignoring the secondary `ICLOUD_SYNC_STORAGE` inquiry.

Root Cause Hypothesis: Single-label intent taxonomy design cannot natively represent multi-intent customer queries without a multi-label classification layer.

Failure Mode #3

Short Context Ambiguity

Real Example: "@AppleSupport it's not working"

Observed Behavior: Low-confidence intent prediction defaults to generic troubleshooting rather than proactively requesting device context.

Root Cause Hypothesis: Zero turn context available in single-tweet queries without multi-turn dialogue history.

Failure Mode #4

Over-Escalation on Routine Hardware Inquiries

Real Example: "@AppleSupport Is fast charging bad for long term battery health?"

Observed Behavior: Escalation engine triggered on keyword "battery health", routing routine informational query to human queue.

Root Cause Hypothesis: Broad keyword regex matching without semantic parsing created false-positive safety triggers.

Failure Mode #5

Outdated System Version Resolution Hallucination

Real Example: "@AppleSupport How do I clear app cache on iOS 17?"

Observed Behavior: Retrieved historical resolution from older iOS versions suggesting non-existent "Clear Cache" settings button.

Root Cause Hypothesis: RAG vector database lacks temporal metadata filtering to deprecate outdated OS troubleshooting steps.

Engineering Decision Log (12 Non-Obvious Decisions)

Documented architectural choices, trade-offs, and rationale behind system design.

  1. Brand Focus on @AppleSupport: Selected @AppleSupport over generic multi-brand handling because customer support models require deep domain-specific resolution grounding.
  2. 6-Class Intent Taxonomy: Bounded taxonomy to 6 operational categories to maximize classification precision and actionable routing.
  3. Deterministic Escalation Safety Rules: Used regex-based safety rules for thermal/smoke hazards over neural classifiers to guarantee zero safety false negatives.
  4. RAG Historical Thread Retrieval: Grounded replies in historical @AppleSupport resolutions rather than un-grounded parametric LLM generation to prevent hallucinated URLs.
  5. Multi-Dimensional LLM-as-Judge: Evaluated reply quality across Tone, Grounding, Helpfulness, and Safety rather than single overall score.
  6. Human Agreement Proof Engine: Integrated Cohen's Kappa & Pearson correlation validation on a 50-item sample to prove judge reliability.
  7. 200-Item Stratified Golden Dataset: Hand-crafted golden set with difficulty levels (simple, ambiguous, frustrated, adversarial) to test real-world robustness.
  8. Sub-15 Minute Reproducibility Target: Engineered zero-external-API pipeline fallback ensuring automated evaluation executes in under 2 seconds.
  9. Dual-Baseline Benchmark Architecture: Implemented both a Trivial Majority Baseline (Baseline 0) and Simple Keyword Baseline (Baseline 1) for honest comparison.
  10. Explicit Escalation Rationale Payload: Configured system to always output a human-readable `escalation_reason` string alongside routing decisions.
  11. Mandatory "Headline Misleading" Analysis: Included rigorous self-critique section in report examining BLEU limitations and offline evaluation biases.
  12. Standalone Web Server Dashboard: Built lightweight Flask + Vanilla CSS dashboard for interactive live testing during evaluator review.
